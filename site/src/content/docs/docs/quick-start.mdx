This page builds a small air conditioner with one capability, `aircon.power.set`. You write it one time. Then you serve it through three surfaces: a command line, an MCP server and an HTTP API.

Choose a core in the tabs. Your choice applies to each step of the page:

| Core | Package | Schemas |
| --- | --- | --- |
| TypeScript | `@acid-cat/core-ts` | [Zod](https://zod.dev), or another Standard Schema library |
| Effect | `@acid-cat/core-effect` | Effect Schema |
| Rust | `acid-cat-core` | Rust types that derive `serde` and `schemars::JsonSchema` |

Each core is one implementation of the [specification](/spec/). All three cores serve the same surfaces, and write the same catalog.

<Aside type="caution">
AcidCat is experimental. The packages are `0.x`, and a minor release can break their APIs. Pin exact versions.
</Aside>

## Before you start

<Tabs syncKey="core">
<TabItem label="TypeScript">

- Node.js 24 or later. Node.js runs the `.ts` files directly.
- A project with `"type": "module"` in its `package.json`.

</TabItem>
<TabItem label="Effect">

- Node.js 24 or later. Node.js runs the `.ts` files directly.
- A project with `"type": "module"` in its `package.json`.
- Effect version 4.

</TabItem>
<TabItem label="Rust">

- Rust 1.85 or later, with Cargo.
- Node.js 24 or later, for the `acid-cat` command that checks the catalog.

</TabItem>
</Tabs>

## Build it

<Steps>

1. **Install the packages.**

   <Tabs syncKey="core">
   <TabItem label="TypeScript">

   <PackageInstall packages={["@acid-cat/core-ts", "zod"]} />

   <PackageInstall packages={["@acid-cat/cli"]} dev />

   `@acid-cat/core-ts` runs the capabilities. `@acid-cat/cli` gives the `acid-cat` command, which you use at build time only.

   </TabItem>
   <TabItem label="Effect">

   <PackageInstall packages={["@acid-cat/core-effect", "effect", "@effect/platform-node"]} />

   <PackageInstall packages={["@acid-cat/cli"]} dev />

   `@acid-cat/core-effect` runs the capabilities. `effect` and `@effect/platform-node` are peer dependencies, so the application and the core share one Effect. `@acid-cat/cli` gives the `acid-cat` command, which you use at build time only.

   </TabItem>
   <TabItem label="Rust">

   ```sh
   cargo new home
   cd home
   cargo add acid-cat-core schemars
   cargo add serde --features derive
   cargo add tokio --features macros,rt-multi-thread
   ```

   `acid-cat-core` runs the capabilities on Tokio. The `acid-cat` command comes from the npm package `@acid-cat/cli`. Step 3 runs it with a package runner, so it needs no `package.json`.

   </TabItem>
   </Tabs>

2. **Declare the capability.**

   A capability has an id, a description, an audience, schemas and a function that does the work. These declarations are the source of the catalog.

   <Tabs syncKey="core">
   <TabItem label="TypeScript">

   ```ts title="aircon.ts"
   import { defineApp, defineCapability, fail, ok } from "@acid-cat/core-ts";
   import type { ToJsonSchema } from "@acid-cat/core-ts";
   import { z } from "zod";

   const unit = { online: true, on: false };

   const powerSet = defineCapability({
     id: "aircon.power.set",
     description: "Turn the unit on or off.",
     audience: ["cli", "mcp", "api"],
     destructive: true,
     idempotent: true,
     input: z.object({ on: z.boolean() }),
     failures: { Offline: z.object({ _tag: z.literal("Offline") }) },
     run: ({ on }) => {
       if (!unit.online) return fail({ _tag: "Offline" });
       unit.on = on;
       return ok(null);
     },
   });

   export const aircon = defineApp({
     title: "Air conditioner",
     targets: {
       cli: { bindings: ["cli"] },
       mcp: { bindings: ["mcp"] },
       api: { bindings: ["http"] },
     },
     capabilities: [powerSet],
   });

   export const toJsonSchema: ToJsonSchema = (schema) => {
     if (!(schema instanceof z.ZodType)) throw new Error("Only Zod schemas.");
     return z.toJSONSchema(schema, { target: "draft-2020-12" });
   };
   ```

   - `run` returns `ok(value)` or `fail(failure)`. A failure is data, with its tag in `_tag`.
   - Standard Schema has no conversion to JSON Schema, so `toJsonSchema` gives the converter of Zod to the core.

   </TabItem>
   <TabItem label="Effect">

   ```ts title="aircon.ts"
   import { App, Capability } from "@acid-cat/core-effect";
   import { Effect, Schema } from "effect";

   const unit = { online: true, on: false };

   const Offline = Schema.TaggedStruct("Offline", {});

   const powerSet = Capability.make({
     id: "aircon.power.set",
     description: "Turn the unit on or off.",
     audience: ["cli", "mcp", "api"],
     destructive: true,
     idempotent: true,
     input: Schema.Struct({ on: Schema.Boolean }),
     failures: [Offline],
     run: ({ on }) =>
       Effect.gen(function* () {
         if (!unit.online) return yield* Effect.fail(Offline.make({}));
         unit.on = on;
         return null;
       }),
   });

   export const aircon = App.make({
     title: "Air conditioner",
     targets: {
       cli: { bindings: ["cli"] },
       mcp: { bindings: ["mcp"] },
       api: { bindings: ["http"] },
     },
     capabilities: [powerSet],
   });
   ```

   - `run` is an Effect. Its value is the value of the call, and its error is a failure.
   - Each failure is a `Schema.TaggedStruct`. Its tag is the failure tag of the catalog.

   </TabItem>
   <TabItem label="Rust">

   ```rust title="src/main.rs (part)"
   use std::sync::Arc;
   use std::sync::atomic::{AtomicBool, Ordering};

   use acid_cat_core::{App, Application, fail};
   use schemars::JsonSchema;
   use serde::{Deserialize, Serialize};

   struct Unit {
       online: AtomicBool,
       on: AtomicBool,
   }

   type Capability = acid_cat_core::Capability<Unit>;

   #[derive(Deserialize, JsonSchema)]
   struct Power {
       on: bool,
   }

   #[derive(Serialize, JsonSchema)]
   #[serde(tag = "_tag")]
   enum Offline {
       Offline {},
   }

   fn aircon() -> Arc<Application<Unit>> {
       App::new()
           .title("Air conditioner")
           .target("cli", ["cli"])
           .target("mcp", ["mcp"])
           .target("api", ["http"])
           .capability(
               Capability::new("aircon.power.set", "Turn the unit on or off.")
                   .audience(["cli", "mcp", "api"])
                   .destructive(true)
                   .idempotent(true)
                   .input::<Power>()
                   .failures::<Offline>()
                   .run(|Power { on }, call| async move {
                       let unit = call.context();
                       if !unit.online.load(Ordering::SeqCst) {
                           return fail(Offline::Offline {});
                       }
                       unit.on.store(on, Ordering::SeqCst);
                       Ok(())
                   }),
           )
           .build()
           .expect("the application conforms")
   }
   ```

   - `Unit` holds the services of the application. `call.context()` gives them to the work.
   - The work returns `Ok(value)` or `fail(failure)`. With no output type, the value is `null`.
   - Each variant of the enum with `#[serde(tag = "_tag")]` is one failure. Its name is the tag.
   - `build()` checks the application, and gives the rules that it breaks, if any.

   </TabItem>
   </Tabs>

   - `targets` names three groups of clients. Each target lists the bindings that serve it.
   - `audience` gives the targets that can use the capability. A target that is not in the audience does not see the capability.
   - `destructive` and `idempotent` are hints. MCP clients get them as `destructiveHint` and `idempotentHint`, so an agent knows to ask before it turns the unit off.

3. **Write the catalog and check it.**

   At build time, write the catalog as JSON. Then check it with `acid-cat check`.

   <Tabs syncKey="core">
   <TabItem label="TypeScript">

   ```ts title="catalog.ts"
   import { writeFile } from "node:fs/promises";
   import { renderCatalog } from "@acid-cat/core-ts";
   import { aircon, toJsonSchema } from "./aircon.ts";

   await writeFile("aircon.acidcat.json", renderCatalog(aircon, { toJsonSchema }));
   ```

   <PackageRun before="node catalog.ts" command="acid-cat check aircon.acidcat.json" />

   </TabItem>
   <TabItem label="Effect">

   ```ts title="catalog.ts"
   import { writeFile } from "node:fs/promises";
   import { App } from "@acid-cat/core-effect";
   import { aircon } from "./aircon.ts";

   await writeFile("aircon.acidcat.json", App.render(aircon));
   ```

   <PackageRun before="node catalog.ts" command="acid-cat check aircon.acidcat.json" />

   </TabItem>
   <TabItem label="Rust">

   One program serves every surface. Its first argument chooses what it does. With `catalog`, it prints the catalog:

   ```rust title="src/main.rs (part)"
   #[tokio::main]
   async fn main() {
       let app = aircon();
       let unit = Arc::new(Unit { online: AtomicBool::new(true), on: AtomicBool::new(false) });
       let args: Vec<String> = std::env::args().skip(1).collect();
       match args.first().map(String::as_str) {
           Some("catalog") => print!("{}", app.render_catalog()),
           _ => {
               eprintln!("Usage: home <catalog|cli|mcp|serve>");
               std::process::exit(2);
           }
       }
   }
   ```

   ```sh
   cargo run -q -- catalog > aircon.acidcat.json
   npx @acid-cat/cli check aircon.acidcat.json
   ```

   </TabItem>
   </Tabs>

   ```txt title="Output"
   The catalog conforms.
   ```

   The core writes the catalog in [canonical form](/spec/catalog/#canonical-form). Commit `aircon.acidcat.json` with the source, and run `acid-cat check` in your build.

4. **Serve it as a command line.**

   <Tabs syncKey="core">
   <TabItem label="TypeScript">

   ```ts title="cli.ts"
   import { cliMain } from "@acid-cat/core-ts";
   import { aircon, toJsonSchema } from "./aircon.ts";

   cliMain(aircon, { name: "home", version: "0.1.0", context: {}, toJsonSchema });
   ```

   ```sh
   $ node cli.ts aircon power set --on
   null
   $ node cli.ts aircon power set --help
   Usage: home aircon power set --on

   Turn the unit on or off.
   ```

   </TabItem>
   <TabItem label="Effect">

   ```ts title="cli.ts"
   import { NodeCli } from "@acid-cat/core-effect/node";
   import { Layer } from "effect";
   import { aircon } from "./aircon.ts";

   NodeCli.main(aircon, Layer.empty, { name: "home", version: "0.1.0" });
   ```

   The capability needs no services, so the layer is `Layer.empty`.

   ```sh
   $ node cli.ts aircon power set --on
   null
   $ node cli.ts aircon power set --help
   Usage: home aircon power set --on

   Turn the unit on or off.
   ```

   </TabItem>
   <TabItem label="Rust">

   Add this arm to the `match` in `main`:

   ```rust title="src/main.rs (part)"
   Some("cli") => {
       use acid_cat_core::cli::{CliOptions, run_cli_process};
       let code = run_cli_process(app, unit, CliOptions::new("home", "0.1.0"), args[1..].to_vec()).await;
       std::process::exit(code);
   }
   ```

   ```sh
   $ cargo run -q -- cli aircon power set --on
   null
   $ cargo run -q -- cli aircon power set --help
   Usage: home aircon power set --on

   Turn the unit on or off.
   ```

   </TabItem>
   </Tabs>

   The command line has one command for each capability in the view of the `cli` target. The segments of the id give the path of the command. The capability has no output schema, so its value is `null`. The command `list` lists every command.

5. **Serve it as an MCP server through stdio.**

   <Tabs syncKey="core">
   <TabItem label="TypeScript">

   ```ts title="mcp.ts"
   import { mcpStdioMain } from "@acid-cat/core-ts";
   import { aircon, toJsonSchema } from "./aircon.ts";

   mcpStdioMain(aircon, { name: "home", version: "0.1.0", context: {}, toJsonSchema });
   ```

   Give the command `node mcp.ts` to your MCP client.

   </TabItem>
   <TabItem label="Effect">

   ```ts title="mcp.ts"
   import { NodeMcp } from "@acid-cat/core-effect/node";
   import { Layer } from "effect";
   import { aircon } from "./aircon.ts";

   NodeMcp.main(aircon, Layer.empty, { name: "home", version: "0.1.0" });
   ```

   Give the command `node mcp.ts` to your MCP client. Effect logs go to standard error.

   </TabItem>
   <TabItem label="Rust">

   Add this arm to the `match` in `main`:

   ```rust title="src/main.rs (part)"
   Some("mcp") => {
       use acid_cat_core::mcp::{McpStdioOptions, serve_stdio};
       serve_stdio(app, unit, McpStdioOptions::new("home", "0.1.0")).await;
   }
   ```

   Run `cargo build`, then give the command `target/debug/home mcp` to your MCP client.

   </TabItem>
   </Tabs>

   The client starts the server as a process. The server has one tool, `aircon.power.set`, with the annotations `destructiveHint: true` and `idempotentHint: true`.

   <Aside type="caution">
   Standard output carries only MCP messages. Never write to standard output from a capability that this server serves.
   </Aside>

6. **Serve it through HTTP.**

   The HTTP binding serves the `api` target, and the MCP binding serves the `mcp` target. One server serves both, by path prefix.

   <Tabs syncKey="core">
   <TabItem label="TypeScript">

   `httpHandler` and `mcpHandler` give web handlers: functions from a `Request` to a `Response`. `serve` from `@acid-cat/core-ts/node` serves them on Node.js.

   ```ts title="serve.ts"
   import { httpHandler, mcpHandler } from "@acid-cat/core-ts";
   import { serve } from "@acid-cat/core-ts/node";
   import { aircon, toJsonSchema } from "./aircon.ts";

   const mcp = mcpHandler(aircon, { name: "home", version: "0.1.0", allowedOrigins: [], toJsonSchema, context: {} });
   const http = httpHandler(aircon, { allowedOrigins: [], toJsonSchema, context: {} });

   const server = await serve({ "/mcp": mcp, "/": http }, { port: 3000 });
   console.log(server.url);
   ```

   Start it with `node serve.ts`.

   </TabItem>
   <TabItem label="Effect">

   `Http.toWebHandler` and `Mcp.toWebHandler` give web handlers: functions from a `Request` to a `Response`. `NodeServer` serves them on Node.js, until its scope closes.

   ```ts title="serve.ts"
   import { Http, Mcp } from "@acid-cat/core-effect";
   import * as NodeServer from "@acid-cat/core-effect/NodeServer";
   import { Console, Effect, Layer } from "effect";
   import { aircon } from "./aircon.ts";

   const mcp = Mcp.toWebHandler(aircon, Layer.empty, { name: "home", version: "0.1.0", allowedOrigins: [] });
   const http = Http.toWebHandler(aircon, Layer.empty, { allowedOrigins: [] });

   Effect.runFork(
     Effect.scoped(
       Effect.gen(function* () {
         const server = yield* NodeServer.serve({ "/mcp": mcp, "/": http }, { port: 3000 });
         yield* Console.log(server.url);
         return yield* Effect.never;
       }),
     ),
   );
   ```

   Start it with `node serve.ts`.

   </TabItem>
   <TabItem label="Rust">

   `HttpBinding` and `McpBinding` are handlers. `remote::serve` serves them by path prefix. Add this arm to the `match` in `main`:

   ```rust title="src/main.rs (part)"
   Some("serve") => {
       use acid_cat_core::http::{HttpBinding, HttpOptions};
       use acid_cat_core::mcp::{McpBinding, McpOptions};
       let mcp = McpBinding::new(app.clone(), unit.clone(), McpOptions::new("home", "0.1.0"));
       let http = HttpBinding::new(app, unit, HttpOptions::default());
       let server = acid_cat_core::remote::serve(
           "127.0.0.1:3000".parse().expect("an address"),
           vec![("/mcp".into(), Arc::new(mcp)), ("/".into(), Arc::new(http))],
       )
       .await
       .expect("the server starts");
       println!("{}", server.url());
       std::future::pending::<()>().await;
   }
   ```

   Start it with `cargo run -q -- serve`.

   </TabItem>
   </Tabs>

   The server prints `http://127.0.0.1:3000`. Call the capability from another terminal:

   ```sh
   $ curl -X POST http://127.0.0.1:3000/capabilities/aircon.power.set \
       -H 'Content-Type: application/json' -d '{"on":true}'
   {"ok":true,"value":null}
   ```

   An input that does not match the schema gets the status 422 and the call failure `invalid-input`. The capability does not run.

</Steps>

## What you have

- One declaration of `aircon.power.set`.
- A catalog, `aircon.acidcat.json`, that `acid-cat check` accepts.
- Three surfaces that take the same input and return the same failure, `Offline`.

The server listens on `127.0.0.1` with plain HTTP. For clients on the network, end TLS on the platform in front of it, and listen on `0.0.0.0`.
