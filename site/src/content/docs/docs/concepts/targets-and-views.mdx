A **target** is a group of clients that can use a set of capabilities, for example `app`, `cli` or `mcp`. The **view** of a target is the part of the catalog that its clients can see. Each binding serves the view of its target, and nothing more.

## Targets in the air conditioner

The air conditioner has five targets: `app`, `taskbar`, `cli`, `mcp` and `api`. Here are three of them:

<CatalogExample target={["app", "cli", "mcp"]} />

| Member | Required | Value |
| --- | --- | --- |
| `bindings` | Yes | The bindings that serve the target |
| `description` | No | The clients of the target |
| `options` | No | Settings for the bindings, in a member with the name of the binding. For example, `options.cli` holds the aliases of the command line |

- You choose the target names. The specification reserves none.
- A target can use more than one binding. A web page can use `typescript` and `webmcp`.
- A binding that the specification does not define has a prefix, such as `acme:swift`.

## The view of a target

The view of a target is itself a catalog. It contains:

- only that target in `targets`;
- only the capabilities and the events whose audience includes that target;
- only the types that these capabilities and events use.

In the air conditioner, the `taskbar` target sees only `aircon.status.get`, `aircon.power.set` and the event `aircon.status.changed`. The `mcp` target does not see `aircon.status.export` or `aircon.firmware.update`.

Print the view of one target with `acid-cat view`:

```sh
acid-cat view aircon.acidcat.json mcp
```

## Outside the view

A client gets no information about a capability or an event outside its view. A call to such a capability fails as a call to an unknown id, `unknown-capability`. The failure is the same when the id exists for a different target, so a client cannot learn about it.

In the air conditioner, the MCP servers, WebMCP and the APIs answer `unknown-capability` for `aircon.status.export`.

## Choose targets for agents

Give agents only the capabilities that they must have. Put the `mcp` target, and each target with the `webmcp` binding, only in the audience of those capabilities.
